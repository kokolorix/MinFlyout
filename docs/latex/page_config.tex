\doxysection{Configuration reference }
\hypertarget{page_config}{}\label{page_config}\index{Configuration reference@{Configuration reference}}
Every key Min\+Flyout understands, what it does, what it defaults to and what happens at the edges of its range. \doxysectlink{page_config_config_examples}{Examples}{1} follows with complete files for a small laptop, two screens of different shape, a tablet that turns, and a session spent chasing an app that stays undetected.

The mechanisms behind the settings are described on the main page: \doxysectlink{index_main_capture}{Writing a zone down without counting pixels}{2} writes a zone down without counting pixels, \doxysectlink{index_main_monitor_layouts}{Layouts for one screen}{2} explains the monitor selectors, \doxysectlink{index_main_detection}{How the button is located}{2} what {\ttfamily "{}button\+Detection"{}} chooses between, and \doxysectlink{index_main_diagnosis}{When a window stays undetected}{2} what to do when a window stays undetected.\hypertarget{page_config_config_file}{}\doxysubsection{\texorpdfstring{The file}{The file}}\label{page_config_config_file}
On first start {\ttfamily \%APPDATA\%\textbackslash{}Min\+Flyout\textbackslash{}config.\+jsonc} is created with a commented template -\/ the same text mfly::\+\+Config\+Store::\+\+Reload writes, so the template and the defaults documented here cannot drift apart.

The format is JSONC, read by the parser in Json.\+h: line comments ({\ttfamily /\+/}), block comments and trailing commas are allowed.

{\ttfamily res/\+config.\+schema.\+json} describes the whole file, so an editor can complete the keys, show these descriptions on hover and flag a typo such as {\ttfamily show\+All\+Monitor}. In VS Code, either add an entry to {\ttfamily json.\+schemas} in the {\bfseries{user}} settings -\/ appending to the array rather than replacing it -\/ with {\ttfamily file\+Match} set to {\ttfamily \&\#42;\&\#42;\&\#47;Min\+Flyout/\+config.\+jsonc} and {\ttfamily url} to the full path of {\ttfamily res/\+config.\+schema.\+json}; or put {\ttfamily "{}\$schema"{}: "{}d:\+/\+\+Projects/\+\+Min\+Flyout/\+res/\+config.\+schema.\+json"{}} as the first key of the file itself. Min\+Flyout ignores keys it does not know, so the file keeps working either way. Forward slashes are accepted in that path and save the escaping.

The trailing commas of the template stay flagged with a warning: the JSONC mode accepts them, but VS Code marks them anyway and offers no setting for that single diagnostic -\/ the only switch is {\ttfamily "{}json.\+validate.\+enable"{}}: {\ttfamily false}, which would also disable the schema.

{\bfseries{Saving applies the changes.}} mfly::\+\+Config\+Watcher watches the folder, debounces for 300 ms and posts one message per save; a balloon on the tray icon confirms the reload. The tray menu entry {\itshape Reload configuration} does the same by hand, and {\ttfamily "{}watch\+Config"{}}: {\ttfamily false} turns the watching off.\hypertarget{page_config_config_top}{}\doxysubsection{\texorpdfstring{Top-\/level keys}{Top-\/level keys}}\label{page_config_config_top}

Numbers outside their range are clamped rather than rejected: a {\ttfamily hover\+Delay\+Ms} of 100000 becomes 5000 and the file still loads. The only values that make the load fail are structural -\/ a {\ttfamily "{}layouts"{}} that is not an array, a {\ttfamily "{}button\+Detection"{}} nobody knows, a malformed {\ttfamily "{}touch"{}}. \doxysectlink{page_config_config_errors}{When the file does not parse}{1} says what happens then.\hypertarget{page_config_config_uiscale}{}\doxysubsection{\texorpdfstring{Making the flyout bigger}{Making the flyout bigger}}\label{page_config_config_uiscale}
Windows sizes the flyout for the resolution of the screen, which on a small panel means small -\/ correct in millimetres, and awkward to hit. {\ttfamily "{}ui\+Scale"{}} multiplies that.

\DoxyCodeLine{"{}uiScale"{}:\ 1.4,}

\end{DoxyCode}


The factor is folded into the DPI the flyout is laid out for (mfly::\+\+Scaled\+Dpi), and every metric already goes through that DPI. Fonts, paddings, corner radii and the miniatures therefore grow together and nothing can be pulled out of proportion -\/ it is the same multiplication a higher-\/resolution screen would apply. Accepted range is mfly::\+k\+Min\+Ui\+Scale to mfly::\+k\+Max\+Ui\+Scale; values below 1 shrink it.

A factor is a wish, not an instruction. On the very screen it is meant for it may ask for more room than there is, so mfly::\+\+Flyout\+Window::\+\+Show compares the measured size with the work area and walks the factor back until it fits -\/ but never below 1.\+0, so asking for a larger flyout can never hand out a smaller one. A reduction is written to the log.

The touch overlay has no such setting: its trigger field and its zones are given in percent of the screen and are therefore already as large as the screen is.\hypertarget{page_config_config_hotkey}{}\doxysubsection{\texorpdfstring{Opening the flyout from the keyboard}{Opening the flyout from the keyboard}}\label{page_config_config_hotkey}
{\ttfamily "{}open\+Hotkey"{}} is the keyboard route to what the hover opens. Pressed, it opens the flyout for the foreground window, below its minimize button -\/ the button is located the way the detection computes it when a window does not answer the hit test (mfly::\+\+Compute\+Minimize\+Button). A window without a minimize button gets the flyout below the middle of its title bar.

Such a flyout ignores where the pointer is. It closes on the same keys again, on Esc, on a click outside it, when a window is chosen in it, and when another window comes to the front. While detection is paused the hotkey does nothing.

The tray menu offers the same as {\itshape Open flyout for the active window}, with the hotkey shown beside it -\/ reachable without a mouse through Win+B, the arrow keys and Enter, and the way out when the combination belongs to some other program. Opening the tray menu puts the taskbar in front, so the entry acts on the window that was in front before (mfly::\+\+App\+Controller::\+\+User\+Window).

Inside the flyout, Tab and Shift+\+Tab move from monitor to monitor (the resize toolbar and the text items are stops as well), the arrow keys move within one, Home and End jump to its ends, Enter and Space choose. The details are at mfly::\+\+Flyout\+Window::\+\+Handle\+Key and mfly::\+\+Hook\+Thread::\+\+Set\+Key\+Navigation.

Spelling (mfly::\+\+Parse\+Hotkey): parts joined by {\ttfamily \textquotesingle{}+\textquotesingle{}}, case and blanks do not matter.

A key other than F1 -\/ F24 needs Ctrl, Alt or Win -\/ {\ttfamily "{}\+Shift+\+A"{}} would swallow every capital A. {\ttfamily Esc} is refused, it is what closes the flyout. An unknown spelling is a configuration error. A combination that another program already holds is reported in a balloon after a reload and in the log; the tray menu entry keeps working.

On keyboard layouts with Alt\+Gr, Ctrl+\+Alt+letter is the same as Alt\+Gr+letter. Z carries no character on the German, Swiss or French layouts; on a layout where it does (Polish ż), pick another key.\hypertarget{page_config_config_zone}{}\doxysubsection{\texorpdfstring{The zone object}{The zone object}}\label{page_config_config_zone}
A mfly::\+\+Zone is a rectangle in percent of the reference area -\/ the work area or the full monitor, depending on {\ttfamily "{}use\+Work\+Area"{}}.

A zone does not have to stay on its monitor. A negative {\ttfamily left} or {\ttfamily top}, or a {\ttfamily left} + {\ttfamily width} ({\ttfamily top} + {\ttfamily height}) beyond 100, lets the window reach onto the neighbouring screen -\/ {\ttfamily \{ "{}left"{}: -\/10, "{}top"{}: 0, "{}width"{}: 60, "{}height"{}: 100 \}} starts a tenth of a screen width to the left of this monitor. The percentages always refer to the monitor the zone is picked on, so the overhang is measured in {\itshape its} width and height, not in those of the neighbour. At least 1 \% of each axis has to stay on the zone\textquotesingle{}s own monitor; a zone lying entirely beside it is dropped. Where there is no neighbouring screen, the overhanging part simply ends up off the desktop.

In the miniature such a tile is cut off at the edge and touches the frame there; the touch overlay likewise only shows the part on this screen. Windows assigns a window to the monitor holding the larger part of it -\/ a per-\/monitor DPI aware application whose larger part lands on a screen with a different scale factor may therefore resize itself after being placed.

The limits are exactly the ones mfly::\+\+Zone\+From\+Window applies to a measured zone (both go through mfly::\+\+Limit\+Zone), so a line produced by Ctrl+\+Alt+\+F11 comes back out of the file as the window it was taken from -\/ including a window hanging over the edge of its screen.

The touch trigger field ({\ttfamily touch.\+trigger}) is the one exception: it has to be reachable on this screen and stays within 0 -\/ 99 / 1 -\/ 100.

Zones are meant to tile the area without overlapping, the way the Windows snap layouts do -\/ but nothing enforces it. Where they do overlap, the smallest one under the pointer wins (mfly::\+\+Smallest\+Hit), so a small tile drawn on top of a large one stays reachable. Fractions are allowed and are how thirds are spelled: {\ttfamily 33.\+33} / {\ttfamily 33.\+34} / {\ttfamily 66.\+66}.\hypertarget{page_config_config_layout}{}\doxysubsection{\texorpdfstring{The layout object}{The layout object}}\label{page_config_config_layout}

Touch has its own layouts because it is a different task. Picking one of five miniatures with a mouse is a menu; doing it with a window already in mid-\/drag is not. So there is exactly {\bfseries{one}} drop target: the first layout in {\ttfamily touch.\+layouts} whose {\ttfamily "{}monitors"{}} selector matches the screen the finger is on (mfly::\+\+Layouts\+For\+Monitor). Leave {\ttfamily layouts} out entirely and the flyout\textquotesingle{}s layouts are used instead, so a configuration that never heard of touch gains the drag route without being edited.

A screen no layout applies to simply shows no field there; the drag stays an ordinary drag, and moving to a screen that has one still works.\hypertarget{page_config_config_errors}{}\doxysubsection{\texorpdfstring{When the file does not parse}{When the file does not parse}}\label{page_config_config_errors}
The application keeps running with the default values and reports line and column of the error -\/ in the flyout as a clickable item, and on reload as a balloon on the tray icon (mfly::\+\+Config::\+error). Nothing is silently half applied: either a load succeeds and replaces the configuration, or the previous values stay in place.

Individual entries are more forgiving than the file as a whole. A layout without a usable zone, a zone that is not an object, a monitor selector that is neither a number nor a string -\/ each is dropped and the rest is kept, because one malformed layout is not worth refusing a whole file over.\hypertarget{page_config_config_examples}{}\doxysubsection{\texorpdfstring{Examples}{Examples}}\label{page_config_config_examples}
